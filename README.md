## Replication at a glance

1. **Start with student and dyad records.** The pseudonymized inputs include one row per child in `students.csv` and one row per directed game decision in `dyads.csv`. The dyad file records who sent tokens to whom and how the sender nominated the partner in the peer survey.
2. **Prepare the main analysis data.** Match each decision with the partner's transfer, classify friendship, compute popularity-based Social Rank and both gaps, then apply the null-model filter. The [main preparation script](code/01_build_main_data.R) writes the two files in `data/generated/main/`. Later analyses reuse these objects in R, read their saved files, or build them on first use.
3. **Reproduce the results.** The R scripts use those datasets to fit the models, run the Supporting Information checks, and write tables and figures. The notebooks present the same analyses step by step. Figures with several panels build each panel separately and assemble them at the end. The notebooks show intermediate tables and plot objects, and introduce repeated panels with an explicit example before using the plotting function.

### Data and measures

The two study CSVs contain pseudonymized records and are archived on [Zenodo](https://doi.org/10.5281/zenodo.24210703). The files and their dictionary are included in `data/raw/`. [Data and measures](notebooks/main/01_data_and_measures.qmd) defines the main variables, explains the filter, and includes the [main data dictionary](data/main_codebook.md). `tokens_sent` and `tokens_received` use the original 0–10 allocation scale before the game multiplier; `coop_gap` is received minus sent in those units. Social Rank is normalized to 0–1 within each classroom before `rank_gap` is computed as sender rank minus receiver rank. The main preparation writes `analysis_students.csv` and `analysis_dyads.csv` in `data/generated/main/`. The student file adds only the two rank measures and `attendance_z` to the raw records.

Significance marks follow the paper and the SI: † p < 0.1, \* p < 0.05, \*\* p < 0.01, \*\*\* p < 0.001.

- **Cooperation GAP** is the number of tokens received from the partner minus the number sent.
- **Friendship type** is mutual friendship, one-sided friendship (sender declares or receiver declares), or non-friendship, based on best-friend nominations.
- **Social Rank** is classroom-specific PageRank on the weighted popularity network, with damping 0.85, rescaled to range from 0 to 1.
- **Social Rank GAP** is the sender’s Social Rank minus the receiver’s.
- **Null-model filter** (SI Algorithm 1) shuffles each sender's allocations across her classmates 1,000 times (seed 109) and scores each transfer by its standardized departure from its simulated values. The top 50% are retained, and a pair enters the filtered regression analysis when both directions are retained. The fixed simulation order is supplied in `data/raw/null_model_order.csv`.

The regressions use `lfe::felm()`. The [codebook](data/codebook.md) defines the input variables and generated measures.

## Main workflows

### Clone and reproduce

Clone the repository:

```sh
git clone https://github.com/melanieoyarzun/friendship-hierarchy.git
cd friendship-hierarchy
```

Install [R](https://cran.r-project.org/) (4.3 or later). In the R console, install the analysis dependencies.

```r
install.packages(c("tidyverse", "here", "igraph", "lfe", "ggraph",
                   "patchwork", "scales"))
```

#### Run the R scripts

Run the command for the results you want from the repository root. The main command reuses the prepared data in `data/generated/main/`, or builds them from `data/raw/` on first use. To rebuild the main data explicitly, run `Rscript code/01_build_main_data.R`.

| Workflow | Command | Outputs |
|---|---|---|
| Main results | `Rscript code/run_all.R main` | Table 1, Figures 1D, 2, and 3, and numbers cited in the main text. See `output/tables/` and `output/figures/`. |
| Main results and Supporting Information | `Rscript code/run_all.R` | The main results plus Supporting Information. See `output/tables/si/` and `output/figures/si/` for the SI files. |

The formatted Table 1 is `output/tables/table1_display.csv`. Main-result scripts check their inputs automatically. `Rscript code/run_figure3.R` reproduces Figure 3 alone.

#### Run the notebooks

For Jupyter, install [JupyterLab](https://jupyter.org/install) and the [R kernel](https://irkernel.github.io/). Start JupyterLab from the repository root and follow the [notebook instructions](notebooks/README.md#running-the-notebooks). **Data and measures** builds the shared analysis data from the raw files, step by step, and saves the two completed tables at the end. The result notebooks reuse prepared objects in the R session, read the saved files, or build missing inputs on first use. For Quarto, install the build dependencies below and run `quarto render notebooks` to execute the analyses and build the viewer.

### Build the notebook viewer and Jupyter files

To regenerate these materials locally, install [Quarto](https://quarto.org/) (1.6 or later). In the R console, install the additional build dependencies.

```r
install.packages(c("knitr", "rmarkdown", "jsonlite"))
```

| Build | Command | Where to find it |
|---|---|---|
| Local preview | `quarto preview notebooks` | Quarto opens the companion website with its sidebar. |
| Static HTML | `quarto render notebooks` | Open `notebooks/_site/index.html` in a browser. |
| Jupyter notebooks | `quarto render notebooks --profile ipynb --to ipynb` | Open the `.ipynb` files beside their `.qmd` sources. |
| Publication layout | `python3 website/build_site.py` after rendering | Open `website/_site/index.html`. Requires Python 3.9 or later. |

Run these commands from the repository root. GitHub Actions renders and publishes the same companion website from the default branch. Earlier `/analysis/` page URLs redirect to their corresponding pages in the unified site.
